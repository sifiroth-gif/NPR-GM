# R6-P1 — paired source prefetch diagnostic

Question: can deterministic host retrieval reduce source-related protocol errors without changing model weights? Six new public synthetic cases, paired direct/prefetch, alternating order; 3 single-source, 2 double-source, 1 zero-source. No private data. Do not use these cases or paraphrases for training or final independent evaluation.

Both arms use fresh Sandbox instances, same pinned GGUF/runtime, system instructions, source IDs, 4 read attempts, 5 model rounds, temperature 0.2, seed 42, max_tokens 384, same outcome ID and cost/time. Remove trusted outcome descriptions from both prompts. Only intervention: host reads all mandatory IDs through ordinary request() before first model call; prefetched facts included explicitly as found results. These reads consume the same budget; the model must still cite every required ID, cannot cite unread/hidden/unauthorized IDs. Extra reads remain subject to normal limits. This experiment has one authorized outcome per case; multi-outcome unions and budget overflow need separate evaluation before production. No commit, no automatic facts_used injection.

Report paired valid/invalid counts, error stage, model/host read attempts, unavailable results, full dialogue elapsed seconds (excluding initial host prefetch and runtime startup). Failures remain in the denominator. Model output/prose not logged; validity is structural only and does not establish semantic grounding. A six-case public diagnostic is insufficient for generalization or training-effect claims; do not compare numerically to prior single smoke as if paired. Scripted unit tests verify mechanism, not inference. Run on standard public Ubuntu CPU runner only, no paid API or GPU.

Commands: python -m unittest discover -s tests -v; python -m npr_gm.prefetch_experiment --model Qwen3.5-4B-Q4_K_M (requires pinned local llama-server). Workflow model-prefetch.yml runs once when introduced. Inspect actual receipt in logs before accepting any inference results. Do not automatically rerun on failure.
