# Спецификация данных v0.1

Каждый обучающий пример: id, group_id (сессия/сцена/арка), source {repo,sha,path,turn_id,digest}, context_snapshot (только доступное ведущему на тот момент), player, chosen, rejected (необязательно), labels, reviewer, review_status, split, rights_status. Synthetic указывается явно, источник — созданный тест, не архив. При неизвестных дельтах не восстанавливать их догадкой. SFT: только approved chosen, chat template оригинальной модели, loss на assistant; DPO позже — подтверждённые контрастные пары на одном контексте. Не использовать eval, его парафразы или эталоны в SFT/DPO. Тренировочные и тестовые группы не пересекаются. Удалить скрытые сведения, не нужные для задачи, и личные данные. Хранить частные данные локально вне Git до разрешения на размещение. Модель обучается поведению, а не текущей истории мира.

Пилот: 100–500 качественных approved примеров при наличии; 500–1000 — возможный второй пакет. Не обещать 13500 за четыре дня. Отдельно сохранить smoke set 24 синтетических кейсов; ни один из них не объявлен обучающим. Для новых примеров сначала экспертное чтение и пометки, потом экспорт JSONL. Никакой автоматической положительной разметки всего архива.

Публичная редакция v0.2: только авторский код, методология, библиография и синтетика. Не публиковать закрытые архивы, манифесты, скрытый канон, PDF, ключи, веса или raw runs. Публичные 24 кейса и их парафразы исключить из обучения; для независимой оценки нужен новый закрытый локальный holdout.

## Дополнение R1: схема разметки
Перед выбором chosen/rejected фиксировать applicable_ids, hard_errors (код C01–C04/C10, span, source_ref, justification), soft_scores (C05–C09/C10, 0–4 или null, reason), adjudication, ambiguity, review_version. Для качества NPC сохранять локально (если установлено источником) goal, value_conflict, knowledge_ref, constraints, action_reason; для драматургии — before_state, after_state, causal_link, available_options, disclosure_channel. Не выводить личность игрока из чата. Не сохранять скрытую цепочку рассуждений или придуманные внутренние мысли реального человека. Истинная мотивация вымышленного NPC может быть неизвестна, пометка unknown. В SFT только проверенные ответы без критических ошибок; предпочтительные пары сравнивать при одинаковом контексте, механике и бюджете. Для спорных примеров статус disputed, исключение до решения. Схема рекомендательная до реализации валидатора R3; публичный regression неизменен.

## R3-K — естественно-научная база
Справочные карточки отделены от игровых SFT/DPO и закрытого holdout. См. KNOWLEDGE_CORPUS.md. Начальный набор draft_reference не допускается к обучению. Потребуются экспертная проверка, права, версия и привязка источника. Синтетические примеры применения, а не перепечатка учебников. Обязательный отдельный доменный тест C11.

## R3 — разделение черновиков и утверждённых данных
Извлечение формирует только private_data/.../candidates.jsonl, review_status=pending, train_eligible=false, с точным commit/path/line/record hash; current delta и gm — материал для разметчика, не prompt. Даже предыдущие записи не автоматически достоверный snapshot. Рецензент реконструирует только допустимое состояние на момент хода, фиксирует source_refs и rights_status, вручную утверждает chosen и применимость C01–C11. Группы с соседними/связанными сессиями объединять по аркам, при возможности разделять кампании. Никакого случайного split отдельных ходов. Экспорт только после явной групповой карты split и экспертной отметки; точные дубликаты smoke блокируются автоматически, смысловые парафразы требуют отдельного контроля. Не считать число извлечённых архивных строк числом готовых SFT примеров.
